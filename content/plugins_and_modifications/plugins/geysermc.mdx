### What does the plugin do?

GeyserMC enables clients from Minecraft Bedrock Edition to join your Minecraft Java server.  

## Usage

<Callout type="info">

Geyser follows the newest Minecraft versions. Right after a new Minecraft release, Geyser and Floodgate can break for a while; stay one version back until they update, and make a backup before any upgrade.

</Callout>

## Easiest way: Auto-Crossplay

Auto-Crossplay is a switch on our Paper, Purpur and Leaf server type (**Paper/Purpur & Leaf by ATBP**, marked Recommended), not a separate server type. If your server runs something else, change to that server type in **Settings** first (make a backup).

1. Open the **Startup** tab and set **Minecraft Version** to the exact version you run.
2. Turn on **Enable Auto-Crossplay** (and **Auto Update ViaVersion** if you want it).
3. Go to **Settings** and press **Reinstall Server**. Geyser and Floodgate are installed for you. Reinstalling keeps your worlds and plugins, but make a backup first anyway.
4. Add a Bedrock port as described below.

Turn the switch on before you press **Reinstall Server**; the reinstall is what installs Geyser.

After you change Minecraft version (for example with **More > Software**), Geyser is not set up again by itself: set the new version in **Startup**, check Auto-Crossplay is still on, and press **Reinstall Server** again.

## Manual install

[Download the plugin](https://geysermc.org/download) and upload the jar into your `plugins` folder. Restart or turn on the server. If you need help installing plugins, check out [this guide](/plugins_and_modifications/installing-plugins).  

Once you've installed it, open the **Network** tab in the panel and add a port from the **Minecraft Bedrock / Geyser** range (see [Adding Ports](/using_the_panel/adding-ports)), then restart. You don't need to edit the Geyser config: when your server has one port from that range, the panel tells Geyser to use it, to use NetherNet and which public address to give players. This also replaces `clone-remote-port`. If you have more than one port from that range, set `port` under `bedrock` in `plugins/Geyser-Spigot/config.yml` (or your Geyser config) to the one you want.

**Fabric:** crossplay works on Fabric with the mod builds of Geyser and Floodgate. Use the mod server type and pick Fabric in the **Startup** tab, then add Geyser, Floodgate and Fabric API with the mod installer in the game panel (or upload the Fabric jars to the `mods` folder yourself). The config is `config/Geyser-Fabric/config.yml` in the **Files** tab (not inside the mod jar). It is created the first time the server starts with Geyser installed, so if the folder is missing, start the server once, stop it, then edit the file. Add a **Minecraft Bedrock / Geyser** port exactly as above and the panel points Geyser at it.

With **Enable Auto-Crossplay** on in the server's **Startup** tab, the Geyser config starts with `clone-remote-port: false`, and reinstalling the server keeps the Geyser config you set.

After that, restart the server. Bedrock players join with your server's IP address and that port.

## Joining from Bedrock

In Bedrock, go to **Play > Servers > Add Server**. Put only the IP address or domain in **Server Address**, without `:` and the numbers after it, and put the Bedrock port from the **Network** tab in the separate **Port** box.

## Bedrock players cannot join

- **NetherNet**: Bedrock 26.60 and newer only connect over NetherNet. The panel turns it on for Geyser and gives Geyser your public address, so you don't change `transport` yourself. Geyser needs build 1237 or newer: if the console says NetherNet is not supported, update Geyser and Floodgate. On first join players may be asked to trust your server; they press trust once. If Bedrock players get "Connection Failed" and the console shows Geyser still listening on `19132` or still using `raknet`, the panel did not set it: stop the server, open `plugins/Geyser-Spigot/config.yml`, set `port` under `bedrock` to your Bedrock port from the **Network** tab, change `transport` from `raknet` to `nethernet`, save and start the server. Players then join with that Bedrock port.
- **Geyser stopped working after a plugin reload**: Geyser does not survive `/reload` or plugin manager tools such as PlugMan. Remove the plugin manager, then fully restart the server from the panel. If Bedrock still cannot join after you edited the Geyser config, stop the server, back up and delete `config.yml` in the Geyser folder, start the server once so a fresh one is made, then set only the Bedrock `port`, `clone-remote-port: false` and (with Floodgate) `auth-type: floodgate`. Always keep a copy before you edit the Geyser config.
- **Some Bedrock players can join and others cannot**: when the server works for some players, the problem is usually the route from the other players' internet provider to Singapore. Ask each player who cannot join to try mobile data or a VPN for a few minutes. If that works, have them run an MTR or traceroute to your server's IP (see [Diagnosing Ping Issues](/extras/ping-issues), which also covers phones) and send the results with their public IPv4 address in a ticket, so we can check the route and our network protection.
- **After a port change**: Bedrock players need the new Bedrock port, and any subdomain still points at the old one. Delete the subdomain and create it again.
- **Port mix-up**: keep your Java port as the **primary** port in the **Network** tab. The Bedrock port is a separate port (do not make it primary) and must match the `port` in the Geyser `config.yml`. After changing it, restart the server.
- **Voice chat stopped working for Bedrock players after a port change**: check that the voice chat port in its config is still listed in your **Network** tab, then restart. See [Simple Voice Chat](/plugins_and_modifications/multiplatform/simple-voice-chat).
- **Console says Geyser started on your Java port, or mentions Warden**: Geyser has no Bedrock port of its own. Add a **Minecraft Bedrock / Geyser** port in the **Network** tab and restart.
- **Joining with the Java port**: Bedrock players must use the Bedrock port from the **Network** tab, not the Java one.
- **Kicked with "Please log into Xbox to join this server"**: Geyser and Floodgate are not working together. Update both to their newest builds, stop the server, delete their config files so fresh ones are made, and leave them at the defaults (the panel sets the Bedrock port for you). Start the server again.
- **Login plugin (such as AuthMe) refuses Bedrock players**: Floodgate puts a `.` in front of Bedrock names, which many login plugins block by default. In AuthMe's `config.yml`, set `allowedNicknameCharacters` to `'[a-zA-Z0-9_.]*'` and restart.
- **Whitelist**: Bedrock names start with a `.` (for example `.Steve`). Add them with `fwhitelist add Steve` (Floodgate) or `whitelist add .Steve`, and op them with `op .Steve`.

Players who are using the console version of Bedrock Minecraft must follow the instructions listed on [this page](https://wiki.geysermc.org/geyser/using-geyser-with-consoles/), as the console version does not allow joining custom servers by default.

If you're also using Floodgate, you will have to set `auth-type` to `floodgate` in your Geyser config.yml.
