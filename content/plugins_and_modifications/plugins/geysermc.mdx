### What does the plugin do?

GeyserMC enables clients from Minecraft Bedrock Edition to join your Minecraft Java server.  

## Usage

<Callout type="info">

Geyser follows the newest Minecraft versions. Right after a new Minecraft release, Geyser and Floodgate can break for a while; stay one version back until they update, and make a backup before any upgrade.

</Callout>

## Easiest way: Auto-Crossplay

Auto-Crossplay is a switch on our Paper, Purpur and Leaf server type (**Paper/Purpur & Leaf by ATBP**, marked Recommended), not a separate server type. If your server runs something else, change to that server type in **Settings** first (make a backup).

1. Open the **Startup** tab and set **Minecraft Version** to the exact version you run.

   ![Game panel Startup tab, Variables: Minecraft Version and Software (Paper, Leaf or Purpur)](/screenshots/panel-startup-minecraft-version.webp)

2. Turn on **Enable Auto-Crossplay** (and **Auto Update ViaVersion** if you want it).

   ![Game panel Startup tab, Variables: the Enable Auto-Crossplay switch that sets up Geyser and Floodgate](/screenshots/panel-startup-auto-crossplay.webp)

3. Go to **Settings** and press **Reinstall Server**. Geyser and Floodgate are installed for you. Reinstalling keeps your worlds and plugins, but make a backup first anyway.
4. Add a Bedrock port as described below.

Turn the switch on before you press **Reinstall Server**; the reinstall is what installs Geyser.

After you change Minecraft version (for example with **More > Software**), Geyser is not set up again by itself: set the new version in **Startup**, check Auto-Crossplay is still on, and press **Reinstall Server** again.

## Manual install

[Download the plugin](https://geysermc.org/download) and upload the jar into your `plugins` folder. Restart or turn on the server. If you need help installing plugins, check out [this guide](/plugins_and_modifications/installing-plugins).  

Once you've installed it, open the **Network** tab in the panel and add a port from the **Minecraft Bedrock / Geyser** range (see [Adding Ports](/using_the_panel/adding-ports)), then restart. You don't need to edit the Geyser config: when your server has one port from that range, the panel tells Geyser to use it, to use NetherNet and which public address to give players. This also replaces `clone-remote-port`. If you have more than one port from that range, set `port` under `bedrock` in `plugins/Geyser-Spigot/config.yml` (or your Geyser config) to the one you want; from the next restart the panel uses that port for Geyser, including the secure connection.

![The Add a port dialog on the Network tab: what the port is for (Minecraft Bedrock / Geyser), the free port range, how many ports, and the Add port button](/screenshots/panel-network-add-port-dialog.webp)

![Game panel Network tab: the Add port button and how many ports you are using](/screenshots/panel-network-add-port.webp)

![Game panel Network tab: the extra Bedrock port for Geyser, labelled Minecraft Bedrock / Geyser](/screenshots/panel-network-geyser-port.webp)

**Fabric:** crossplay works on Fabric with the mod builds of Geyser and Floodgate. Use the mod server type and pick Fabric in the **Startup** tab, then add Geyser, Floodgate and Fabric API with the mod installer in the game panel (or upload the Fabric jars to the `mods` folder yourself). The config is `config/Geyser-Fabric/config.yml` in the **Files** tab (not inside the mod jar). It is created the first time the server starts with Geyser installed, so if the folder is missing, start the server once, stop it, then edit the file. Add a **Minecraft Bedrock / Geyser** port exactly as above and the panel points Geyser at it.

With **Enable Auto-Crossplay** on in the server's **Startup** tab, the Geyser config starts with `clone-remote-port: false`, and reinstalling the server keeps the Geyser config you set.

After that, restart the server. Bedrock players join with your server's IP address and that port.

## Joining from Bedrock

In Bedrock, go to **Play > Servers > Add Server**. Put only the IP address or domain in **Server Address**, without `:` and the numbers after it, and put the Bedrock port from the **Network** tab in the separate **Port** box.

## Bedrock players cannot join

- **NetherNet**: Bedrock 26.60 and newer only connect over NetherNet. The panel turns it on for Geyser and gives Geyser your public address, so you don't change `transport` yourself. Bedrock 26.60 players need Geyser build 1273 or newer: if the console says NetherNet is not enabled or not supported, or Geyser's build number is lower, download the newest Geyser and Floodgate for your platform from [geysermc.org](https://geysermc.org/download), replace the old jars and restart. Bedrock players join with your server's IP or subdomain and the Bedrock port. Both connect securely from the server's next restart, so players are not asked to trust it; if a player joining by IP still is, give them the subdomain. If Bedrock players get "Connection Failed" and the console shows Geyser still listening on `19132` or still using `raknet`, the panel did not set it: stop the server, open `plugins/Geyser-Spigot/config.yml`, set `port` under `bedrock` to your Bedrock port from the **Network** tab, change `transport` from `raknet` to `nethernet`, save and start the server. Players then join with that Bedrock port.
- **You added `transport` to the startup command**: remove it. A setting such as `transport=both` in the **Startup** tab overrides what the panel sets, and Bedrock players get timed out even though the port and the Geyser config look right. Clear it, restart the server, and test with a Bedrock player.
- **Geyser stopped working after a plugin reload**: Geyser does not survive `/reload` or plugin manager tools such as PlugMan. Remove the plugin manager, then fully restart the server from the panel. If Bedrock still cannot join after you edited the Geyser config, stop the server, back up and delete `config.yml` in the Geyser folder, start the server once so a fresh one is made, then set only the Bedrock `port`, `clone-remote-port: false` and (with Floodgate) `auth-type: floodgate`. Always keep a copy before you edit the Geyser config.
- **Bedrock stopped working after you added a Geyser extension or pack**: an extension or a custom pack can break every Bedrock connection, while Java players and the console look fine. Make a [backup](/using_the_panel/backups/guide), stop the server, move the ones you added last out of the `extensions` and `packs` folders in your Geyser folder, then start the server and test. Deleting one only counts after a restart, because a running server keeps what it loaded. Add them back one at a time to find the one at fault, and check for a build made for your Geyser version.
- **Some Bedrock players can join and others cannot**: first make sure the players who cannot join have updated Minecraft (Bedrock 26.50 and older cannot connect over NetherNet), that they join with the Bedrock port (see NetherNet above), and that the server was restarted since. If the IP doesn't work for them, try the subdomain. If it still works for some players only, the problem is usually the route from the other players' internet provider to Singapore. Ask each player who cannot join to try mobile data or a VPN for a few minutes. If that works, have them run an MTR or traceroute to your server's IP (see [Diagnosing Ping Issues](/extras/ping-issues), which also covers phones) and send the results with their public IPv4 address in a ticket, so we can check the route and our network protection.
- **"Terracotta" error (`InitialConnection-149`)**: the player's game could not finish the NetherNet connection. Check the server is on Geyser build 1273 or newer and has its own Bedrock port (see above), that the player has updated Minecraft and joins with the Bedrock port, then restart the server. If it still fails by IP, try the subdomain. If it still happens for some players only, have them try mobile data, and send us the time it happened and the player's public IP in a ticket.
- **After a port change**: Bedrock players need the new Bedrock port, and any subdomain still points at the old one. Delete the subdomain and create it again.
- **Port mix-up**: keep your Java port as the **primary** port in the **Network** tab. The Bedrock port is a separate port (do not make it primary) and must match the `port` in the Geyser `config.yml`. After changing it, restart the server.
- **Another plugin uses the Bedrock port**: Geyser needs its port for itself, over both TCP and UDP. Voice chat, a web map (Dynmap, BlueMap), the query port or a website on the same port stops Bedrock players from finding the server. Give each of those its own port from the **Network** tab and restart.
- **Console says the address is a loopback address**: `address` under `bedrock` in the Geyser config is set to `127.0.0.1`. Set it back to `0.0.0.0` and restart, or players cannot reach Geyser.
- **Voice chat stopped working for Bedrock players after a port change**: check that the voice chat port in its config is still listed in your **Network** tab, then restart. See [Simple Voice Chat](/plugins_and_modifications/multiplatform/simple-voice-chat).
- **You used `clone-remote-port`, or the console says Geyser started on your Java port or mentions Warden or NXS**: NetherNet cannot share the Java port, so Geyser needs a Bedrock port of its own. Add a **Minecraft Bedrock / Geyser** port in the **Network** tab and restart; the panel points Geyser at it. Tell your players the new port: Bedrock players who joined with your Java port now join with the Bedrock port.
- **Joining with the Java port**: Bedrock players must use the Bedrock port from the **Network** tab, not the Java one.
- **Kicked with "Please log into Xbox to join this server"**: Geyser and Floodgate are not working together. Update both to their newest builds, stop the server, delete their config files so fresh ones are made, and leave them at the defaults (the panel sets the Bedrock port for you). Start the server again.
- **Login plugin (such as AuthMe) refuses Bedrock players**: Floodgate puts a `.` in front of Bedrock names, which many login plugins block by default. In AuthMe's `config.yml`, set `allowedNicknameCharacters` to `'[a-zA-Z0-9_.]*'` and restart.
- **Bedrock players can join but cannot chat**: stop the server, set `enforce-secure-profile=false` in `server.properties`, save and start it again.
- **Older Fabric server and the newest Bedrock version**: new Geyser builds follow the newest Minecraft Java version. On Paper, [ViaVersion](/running_a_server/join-from-any-version) lets the newest Geyser run on an older server, but on Fabric it does not, so you must use the Geyser build made for your Fabric version. If that build is too old for your players' Bedrock version, update the server to the newest Java version (back up first).
- **Modded servers**: Bedrock players cannot install Java mods, so they cannot join a server whose mods must also be on the player's game. Server-only mods are fine.
- **Bedrock players rubber-band or lag while Java players are fine**: first run `geyser version` in the console. If it says Geyser is behind, download the newest Geyser and Floodgate, replace the old jars in your `plugins` folder (`mods` on Fabric) and restart, because an old build often causes this. If Geyser is current, the cause is almost always the lagging player's connection, which Bedrock movement shows much more than Java. If `moved-wrongly-threshold` and `moved-too-quickly-multiplier` in `spigot.yml` are still at the Spigot defaults, raising them makes the server pull them back less often (Auto Optimization servers already have them raised). See [Bedrock players rubber-band](/extras/ping-issues#minecraft-bedrock-players-rubber-band-but-java-players-are-fine) for values and what else helps.
- **Whitelist**: Bedrock names start with a `.` (for example `.Steve`). Add them with `fwhitelist add Steve` (Floodgate) or `whitelist add .Steve`, and op them with `op .Steve`.

Players who are using the console version of Bedrock Minecraft must follow the instructions listed on [this page](https://wiki.geysermc.org/geyser/using-geyser-with-consoles/), as the console version does not allow joining custom servers by default.

If you're also using Floodgate, you will have to set `auth-type` to `floodgate` in your Geyser config.yml.

## What Bedrock players cannot do through Geyser

Bedrock players are still playing Bedrock, so some things work differently and no plugin changes them:

- **Off-hand:** Geyser's `/geyser offhand` command swaps an item into the off-hand slot, but Bedrock itself mostly treats that slot as storage.
- **PvP:** Bedrock players keep Bedrock's combat controls and feel. There is no plugin that gives them Java PvP.
- **Client mods:** Java mods for the player's game do not work on Bedrock.
- **Bedrock add-ons:** add-ons (behavior packs) do not work on a Java server with Geyser. Geyser can only send resource packs, which go in the `packs` folder in your Geyser folder. For gameplay features, use a Java plugin, or run a Bedrock server if you need add-ons.

If something only goes wrong for Bedrock players, such as blocks that cannot be broken or an item action that fails until the server restarts, update Geyser to its newest build first. If it stays, report it to the Geyser project.
