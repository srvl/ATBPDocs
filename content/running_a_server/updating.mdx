## How to update or change version

Updating keeps your worlds, plugins and settings, so it does not reset your progress. The server only has to stop and start again. Just remember you can't go back to an older version afterwards without a backup, as explained below.

Read the precautions below first, then make a backup.

1. In the [panel](https://panel.atbphosting.com), open your server and go to **More > Software**. The top of the page shows what the server runs now.
2. Pick the software (for example Paper, Purpur, Leaf, Fabric, Forge or NeoForge) and an exact version, then install it. Folia and Canvas are listed only on plans with 8 vCPU or more; see [Server Software](/running_a_server/server-software-overview).
3. The install runs in the background. If the server is running, the panel stops it first. An **Installing** box shows each step (stopping the server, preparing the files, downloading, setting the startup command). You can leave the page and come back; the install keeps going.
4. When the box goes away and the page shows the new version, start the server and check the **Console**.

Only one version change runs at a time on a server. If one is still running, the page says so and you wait for it to finish. If an install does not finish, the page shows **The install did not finish** with the reason. Read the message, check the server's files, then install again.

Switching a fresh server to a mod loader such as Fabric, Forge or NeoForge? Turn on **Wipe Server Files** in the install window so nothing from the old software is left behind. It deletes everything on the server, worlds included, so only use it on a server you have nothing on yet or after a backup. Once the server has started once, add mods under **More > Mods**.

![The panel's More > Software page: Java and Bedrock tabs, a category filter and software such as Paper, Purpur, Fabric and Forge with their version counts](/screenshots/panel-more-software.webp)

Using crossplay? After a version change, set the same version in the **Startup** tab and press **Reinstall Server** in **Settings** so Geyser is set up for it. See [GeyserMC](/plugins_and_modifications/plugins/geysermc).

On a **Vanilla Bedrock** server, if **Software** is not listed, set the version in the **Startup** tab and press **Reinstall Server** in **Settings**.

## Precautions

<Callout type="warning">

Before updating or changing Minecraft versions, create and test a backup of your entire server. You can upgrade Minecraft servers, but you can't go back to a previous version unless you reset your worlds or restore a backup that was made when the server was on the previous version. Downgrading a world without causing corruption is near impossible.

</Callout>

If you aren't using our completely free and automatic backup feature yet, we highly suggest you set it up before updating.

## Before and after a change

<Callout type="warning">

Only delete or wipe server files when you want to start over. Changing software with that option on deletes **everything**, including worlds and plugins. Download a backup first.

</Callout>

Moving from Paper, Spigot or Purpur to Fabric, Forge, NeoForge or Vanilla? Those keep the Nether and End inside the `world` folder, so they won't see your `world_nether` and `world_the_end` folders and those dimensions look empty. Take a backup, then follow [Converting Bukkit worlds to vanilla](/running_a_server/converting-worlds) before you start the new software. Going back to Paper? That page also shows where the Nether and End folders go.

Pick an exact version number rather than "latest". With "latest", a later reinstall can quietly upgrade your server to a new Minecraft version that your plugins do not support yet.

On our Paper, Purpur and Leaf egg, a reinstall never puts an older Minecraft version on a world that was last run on a newer one. The install stops, keeps your current server jar and settings, and the install log in the console says why. Pick the same or a newer version, or move the world folder out first if you really want to start the older version fresh.

Changing version can also need a different Java version. If the server will not start after a change, see [Change Java Version](/running_a_server/java-version).

After you have followed the steps above, you can run your server and test out your new version.

You can periodically check the **Settings** tab, and you will see a **New build available! We recommend to update to the latest build.** message if a new build of the server jar is available.

## Turning a modpack server into a normal server

The modpack source box only changes the modpack. Setting it to nothing does not turn the server into a plain Fabric, Forge or Paper server. To do that:

1. Make a [backup](/using_the_panel/backups/guide) first.
2. Go to **More > Software**, pick the software (for example Fabric or Paper) and an exact version, and install it.
3. Turn on **Wipe Server Files** if you want a clean start without the old modpack files. This deletes everything, including worlds, so only do it with a backup you can restore.
4. Start the server. Re-upload the world and any plugins or mods you want to keep.

Paper does not run mods. If you need a mod loader, pick Fabric, Forge or NeoForge instead.

## Switching to a different modpack (for example Forge to Fabric)

A new modpack does not replace the old one's files by itself, so mods from the old loader stay behind and stop the server from starting. Start clean:

1. Make a [backup](/using_the_panel/backups/guide), and download any world you want to keep.
2. Stop the server, open **Files**, select everything and delete it.
3. In **More > Software**, pick the loader the new pack needs, such as Fabric, at the pack's exact Minecraft version. Then press **Reinstall Server** in **Settings**.
4. Install the pack from **More > Modpacks**. If the pack is on Modrinth, install it from there.
5. Start the server and read the **Console**. If it stops with errors, the log names the mod: a missing dependency to add (often a library mod at a specific version), or a client-only mod to remove. See [Client-side mods](/running_a_server/troubleshooting/client-side-mods).

Players must use the same modpack and version as the server. If they still cannot join, copy the server's `mods` folder list and compare it with theirs.

## Updating the server manually

- [Create a full backup](/using_the_panel/backups/guide) of your server. As an additional step, we suggest testing this backup on a local or a split test server.
- Remove your current server jar through [SFTP](/using_the_panel/sftp) or the [File Manager](/using_the_panel/file-manager-controls).
- Download the new version of your server software. If you are unsure which one to use, check out our guide on server jars [here](/running_a_server/jars).
- Upload it using SFTP or the File Manager and make sure to define the full name (such as `paper-1.18-023`) in the 'Startup' tab on the panel.

## After a new Minecraft release

Right after a new Minecraft release many plugins and mods are not ready. Stay on the previous version until your plugins say they support the new one, and make a backup first. Run `ver` in the console to see which version you are on. Going back is only safe with a backup made before the upgrade: a world that was already opened on the newer version may not load on the older one. Never set a played world back to an older version to "undo" an update; restore the backup from before the upgrade instead.

If you already switched to an older version and your world now looks empty or brand new, or the server crashes on start, your world is usually still there: the older version just cannot read it. Stop the server, switch back to the exact version the world was last played on (the server's `version_history.json` file shows it), and start again. Don't delete or rename the world folder, and don't restore an old backup over it, until you have tried that.
