Schedules run tasks for you at set times: restart the server, send a command, make a backup, clean up files or post to Discord. Open your server in the [panel](https://panel.atbphosting.com) and go to the **Schedules** tab.

## Create a schedule


![The Schedules page with Presets, Import and Create schedule buttons](/screenshots/panel-schedules.webp)

1. Press **Create Schedule** and give it a name.
2. Pick when it runs. Choose a common time from the picker (for example every day at 4 AM) or type the cron fields yourself. Times use the panel's time zone.
3. Save, then open the schedule from the list and press **Add step** to add what it should do.
4. Make sure the schedule is turned on.

When presets are offered, **Start from a preset** gives you a ready-made schedule that you can change after adding it.

## What a step can do

- **Send command**: a console command, typed without the `/` (for example `say Restarting in 5 minutes`).
- **Power action**: start, stop, restart or kill the server.
- **Create backup**: tick **Wait for the backup to finish** so the next step only runs once the backup is done.
- **Delete files**, **Write to file**, **Copy files** and **Move or rename**: tidy up logs, reset a config, rotate a world.
- **Discord webhook**: post a message to your Discord channel through a webhook link.

Each step can have a delay, which is how you space out restart warnings (for example warn, wait 4 minutes, warn again, wait 1 minute, restart). Each step can also either stop the schedule or carry on if it fails.

## Workflows with conditions

Press **Turn into a workflow** to use the visual builder. Steps stack from top to bottom, and you can drag a step by its handle to reorder it or click a gap between steps to add one there.

- **Add condition** splits the workflow into a "true" lane and a "false" lane. A condition can check whether the server is running, whether a file exists or how big it is, CPU, memory or disk use, how many backups you have, whether the previous step worked, the time of day, or the day of the week.
- **Run only when** checks happen before anything runs. Pick **Every check must pass** or **Any one check must pass**. When they fail, the run is recorded as skipped.
- **Run history** shows every run and the result of each step. **Cancel this run** stops a workflow that is running.
- **Back to a plain schedule** removes the conditions and keeps the steps in their order.

## Copy a schedule

**Duplicate this schedule** makes a copy, and **Download this workflow as a file** saves it so you can **Import** it on another server. Copied and imported schedules start turned off, so check them before you turn them on.

## Tips

- The command to warn players differs by game:

| Game | Warning command |
| --- | --- |
| Minecraft | `say Restarting in 5 minutes` |
| Terraria | `say Restarting in 5 minutes` |
| Rust | `say "Restarting in 5 minutes"` |
| Project Zomboid | `servermsg "Restarting in 5 minutes"` |
| 7 Days to Die | `say "Restarting in 5 minutes"` |
| Palworld | `Broadcast Restarting_in_5_minutes` |

- A daily restart helps games that use more memory the longer they run, such as Palworld.
- Back up before a restart, not during busy hours. Daily backups are enough for most servers; very frequent backups on a big world can cause lag.
- A schedule can hold a limited number of steps. If you hit the limit, split the job into two schedules.
