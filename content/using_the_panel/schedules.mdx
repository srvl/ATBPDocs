Schedules run tasks for you at set times: restart the server, send a command, make a backup, clean up files or post to Discord. Open your server in the [panel](https://panel.atbphosting.com) and go to the **Schedules** tab.

## Create a schedule


![The Schedules page with Presets, Import and Create schedule buttons](/screenshots/panel-schedules.webp)

1. Press **Create Schedule** and give it a name.
2. Pick when it runs. Choose a common time from the picker (for example every day at 4 AM) or type the cron fields yourself. Times use the panel's time zone.
3. Save, then open the schedule from the list and press **Add step** to add what it should do.
4. Make sure the schedule is turned on.

When presets are offered, **Start from a preset** gives you a ready-made schedule that you can change after adding it.

## What a step can do

- **Send command**: a console command, typed without the `/` (for example `say Restarting in 5 minutes`).
- **Power action**: start, stop, restart or kill the server.
- **Create backup**: tick **Wait for the backup to finish** so the next step only runs once the backup is done. When your backup slots are full, it deletes your oldest unlocked backup first (never an Auto Backup), so lock the ones you want to keep.
- **Delete files**, **Write to file**, **Copy files** and **Move or rename**: tidy up logs, reset a config, rotate a world.
- **Discord webhook**: post a message to your Discord channel through a webhook link.

Steps run from top to bottom. Each step can have a delay (offset), counted in **seconds** from when the schedule starts, which is how you space out restart warnings. Put the warnings first and the restart last. For a 3 minute warning:

| Step | Action | Delay |
| --- | --- | --- |
| 1 | Send command `say Restarting in 3 minutes` | 0 |
| 2 | Send command `say Restarting in 2 minutes` | 60 |
| 3 | Send command `say Restarting in 1 minute` | 120 |
| 4 | Power action: Restart | 180 |

So a restart 10 minutes after the warning needs a delay of `600`, not `10`. Press **Run now** on the schedule to test it once. Each step can also either stop the schedule or carry on if it fails.

## Running at several times a day

To restart at, say, 3 AM, 12 noon and 5 PM, either make one schedule per time, or type the hours together in the hour field of one schedule (`3,12,17`, with minute `0`).

**Only When Server Is Online** makes the schedule run only while the server is running. Leave it on for restarts and in-game messages. Turn it off if the schedule should also run while the server is off, for example a daily **Start** that brings back a server that was stopped.

## Conditions

A schedule can run some steps only when something is true. Inside a schedule, an **If** step opens a block and **End if** closes it; an **Else** step in between starts the steps that run when the condition is false. The panel's own conditions check whether the server is running, how long it has been up, CPU, memory or disk use, and whether a file exists.

For the other checks, press **Add condition** on the Schedules page:

- **File size**: a file or folder is over, under or exactly a size (for example `logs/latest.log` over 100 MB).
- **Backup count**: how many finished backups the server has.
- **Time window**: the time is between two times, for example `22:00` to `06:00`. Your browser's time zone is used.
- **Day of the week**: today is one of the days you tick.

Pick the schedule, the condition, and which of its steps should run when it is true (or none, and move steps into the block later). Tick the "otherwise" option to also get an **Else** lane. The helper adds two steps: an HTTP request that asks the panel the question, and an **If** on its answer. A check that cannot be answered, for example because the file is missing, counts as false.

HTTP request steps can only call Discord webhooks (and these panel checks).

## Run history

Under the list of schedules, **Run history** shows the runs of all your schedules, newest first, and you can filter it by schedule. Click a run to see every step: whether it ran, failed or was skipped by a condition, which way each condition went, how long each step took, and what each panel check found (for example "logs/latest.log is 12.4 MiB"). The last 200 runs of each schedule are kept. Runs from the old panel (before November 2026) are listed too.

## Copy a schedule

**Duplicate this schedule** makes a copy, and **Download this workflow as a file** saves it so you can **Import** it on another server. Copied and imported schedules start turned off, so check them before you turn them on.

## Tips

- The command to warn players differs by game:

| Game | Warning command |
| --- | --- |
| Minecraft | `say Restarting in 5 minutes` |
| Terraria | `say Restarting in 5 minutes` |
| Rust | `say "Restarting in 5 minutes"` |
| Project Zomboid | `servermsg "Restarting in 5 minutes"` |
| 7 Days to Die | `say "Restarting in 5 minutes"` |
| Palworld | `Broadcast Restarting_in_5_minutes` |

- A daily restart helps games that use more memory the longer they run, such as Palworld.
- Back up before a restart, not during busy hours. Daily backups are enough for most servers; very frequent backups on a big world can cause lag.
- A schedule can hold a limited number of steps. If you hit the limit, split the job into two schedules.
