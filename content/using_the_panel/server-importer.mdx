---
title: "Server Importer"
description: "Copy your files from another host or another ATBP server into your server with the panel's SFTP importer."
---

The Server Importer copies files from another server straight into your ATBP server over SFTP. Use it when you move from another host, or from one ATBP server to another (for example after changing plans), without downloading and uploading everything yourself.

## Before you import

1. [Make a backup](/using_the_panel/backups/guide) of the server you are importing into, and stop it.
2. Read the notice at the top of the importer and do what it asks before you connect.
3. Get the SFTP details of the server you are copying **from**:
   - **From another host:** their panel or support shows the SFTP host, port, username and password.
   - **From another ATBP server:** open that server on the [panel](https://panel.atbphosting.com) and go to **Settings**. The SFTP host, port and username are listed there, see [Using SFTP](/using_the_panel/sftp).

## The fields

| Field | What to enter |
|---|---|
| **Host** | The SFTP address of the old server, without `sftp://` and without the port. |
| **Port** | The SFTP port of the old server. It is often `22`, but many game hosts use another port such as `2022`. Use the one you were given. |
| **Username** | The full SFTP username. On ATBP it is your panel username followed by a dot and the server ID, copied from **Settings**. |
| **Password** | The password for that SFTP login. For an ATBP server this is your **game panel** password, not your email password and not your billing password. |
| **Source path** | The folder on the old server to copy from. `/` copies the whole server. |
| **Destination path** | The folder on this server to copy into. `/` is the top of your server's files. |

**Saved Profiles** keeps these details so you don't have to type them again. Fill in the fields, then click **Save**.

## Running the import

1. Fill in the fields and click **Connect**.
2. Start the import and wait. Large worlds and modpacks can take a while.
3. Open **Files** and check that your world, configs and `plugins` or `mods` folders arrived where you expected.

## After the import

The importer copies files only, not the server's settings. Before you start the server:

- In **Startup** or **Software**, pick the same software and Minecraft version the old server used (Paper, Fabric, NeoForge and so on). Starting the files on different software can remove or ignore your mods and plugins. See [Server Software Overview](/running_a_server/server-software-overview).
- Pick the Java version that matches that Minecraft version, see [Java Version](/running_a_server/java-version).
- If mods or plugins still do not load, check the console for the first error and see [Installing Mods](/plugins_and_modifications/mods-install).

## Troubleshooting

- **It cannot connect to the remote server, or says connection refused or timed out:**
  - Check the host has no `sftp://` and no `:port` in it, and that the port is the SFTP port, not the game port.
  - Use the full SFTP username, including the part after the dot.
  - Set **Source path** to `/`. A folder that does not exist on the old server makes the import fail.
  - Some hosts only allow SFTP from certain places or turn it off for expired servers. If it still fails, download your files from the old server as a `.zip` or `.tar.gz` (or a backup), upload the archive in **Files** (or with [SFTP](/using_the_panel/sftp) for big files), then click **...** next to it and **Unarchive**.
- **Authentication failed:** the username or password is wrong. Passwords are case-sensitive. For an ATBP server, reset your game panel password if you are not sure of it.
- **Files went to the wrong place:** if everything ended up inside an extra folder, move the files up to the top level in **Files**, or run the import again with a different **Destination path**.

Still stuck? Open a [support ticket](/general/getting-support) with the panel link of the server you are importing into.
