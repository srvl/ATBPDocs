### Overview
Databases can be used by certain plugins to allow for a more efficient, organized method of storing large amounts of data. Common Minecraft plugins that use MySQL are Dynmap, CoreProtect and LuckPerms. FiveM frameworks need one too, see [Set up your FiveM database](/games/fivem/database).

### Database Storage
Please keep your database usage reasonable and in line with the Terms of Service at https://atbphosting.com/terms.

### Adding MySQL Databases


![The Databases page with the New database button](/screenshots/panel-databases.webp)

From the [panel](https://panel.atbphosting.com) select the **Databases** tab on the navigation bar.

Click **New Database** to start the process.

In the first box, you assign the database a name. In the second, you can specify what IP addresses can connect to the database. We recommend leaving it as the default wildcard of `%`.

Click a database row to see its host, username and password.

Panel databases can only be used by servers running on ATBP's own network, for example your plugins. They cannot be reached from the internet, so tools on your own computer such as HeidiSQL, or plugins on another host will be refused. To get your data out, use the export option in the panel.

---

### Managing Databases

Once you have created the database, it will appear in your database list. From here you can view basic details, advanced details, import to the database, export from the database, or delete the database.

---
### Importing MySQL Databases through the panel

To import a database you first have to create a new database in your server. Once it is created, you can then click on the import button which will open a prompt. Fill in the form with the database connection details from the remote MySQL server. An import from another server copies at most 2 million rows or 512 MB and stops after 4 minutes; for anything bigger, export it to a .sql file and import that in parts. You can run 3 imports from another server and 10 file imports per server every 10 minutes. Importing needs the permission to see the database password, and replacing existing tables also needs the permission to delete databases.

---
### Importing an .SQL database dump through the file manager

You can also upload an SQL file to import a database. A file import takes files up to about 49 MB; for a bigger one, split it into parts or ask us in a ticket. Once the file is uploaded, go to the file manager, click the three dots to the right of the .sql file and click on **Import Database**, then select the database you want to import it to. Keep in mind that not all .sql files are in the correct format, and this option may not work if the file wasn't properly dumped from a MySQL server. The size on the database row can show 0 B for a few minutes after an import. If you get an error, check that the file really is a MySQL or MariaDB export; files from other database types, such as SQLite, usually will not work.

---
### If a plugin cannot connect

Read the first error the plugin prints in the **Console**, not the long list of lines under it.

| Error | What to do |
| --- | --- |
| `SSL Connection required, but not provided by server` | The plugin is set to use SSL, which panel databases do not use. Turn SSL off in the plugin's config and restart. In AuthMe that is `mySQLUseSSL: false` in `plugins/AuthMe/config.yml`. In plugins that take connection options, add `useSSL=false`, as in the examples below. |
| `Communications link failure` or `Connect timed out` | Check the host and port are copied exactly from the panel. `localhost` and `127.0.0.1` do not work, because the database is on a separate machine. If they are right, the same message can come from the SSL setting above, so check that too. |
| `Access denied for user` | The username or password is wrong. Copy them again from the database's details. |
| `Unknown database` | The database name is wrong. It looks like `s123_name`. |

---
The examples below use placeholders. Copy your real host, port, database name, username and password from the **Databases** tab (the details button) in the panel.

### Examples of how to configure a database in different plugins
#### Luckperms:
```YAML
storage-method: MySQL

# The following block defines the settings for remote database storage methods.
#
# - You don't need to touch any of the settings here if you're using a local storage method!
# - The connection detail options are shared between all remote storage types.
data:

  # Define the address and port for the database.
  # - The standard DB engine port is used by default
  #   (MySQL: 3306, PostgreSQL: 5432, MongoDB: 27017)
  # - Specify as "host:port" if differs
  address: <your database host>:3306

  # The name of the database to store LuckPerms data in.
  # - This must be created already. Don't worry about this setting if you're using MongoDB.
  database: s178_test

  # Credentials for the database.
  username: u178_uIxN5UjEZy
  password: '@CSyH7IV8r4TUnaA3A7lu^2T'
```
#### LiteBans
```YAML
sql:
  # H2, MySQL, MariaDB, and PostgreSQL are supported database drivers.
  driver: MySQL

  ## MySQL/PostgreSQL settings ##
  # If using H2, the database will be stored in the LiteBans plugin folder,
  # and most of these settings won't apply.

  # Database server address.
  address: <your database host>:3306

  # Database name, username and password.
  database: 's178_test'
  username: 'u178_uIxN5UjEZy'
  password: '@CSyH7IV8r4TUnaA3A7lu^2T'
```
#### CoreProtect
```YAML
use-mysql: true
table-prefix: co_
mysql-host: <your database host>
mysql-port: 3306
mysql-database: s178_test
mysql-username: u178_uIxN5UjEZy
mysql-password: @CSyH7IV8r4TUnaA3A7lu^2T
```
#### Plan
```YAML
Database:
    Type: MySQL
    MySQL:
        Host: <your database host>
        Port: 3306
        User: u178_uIxN5UjEZy
        Password: @CSyH7IV8r4TUnaA3A7lu^2T
        Database: s178_test
        # Launch options to append after mysql driver address
        Launch_options: "?rewriteBatchedStatements=true&useSSL=false&serverTimezone=UTC"
```
#### AdvancedBan
```YAML
# If set to false all bans will be saved locally in a HSQLDB-Database
UseMySQL: true

MySQL:
  IP: <your database host>
  DB-Name: s178_test
  Username: u178_uIxN5UjEZy
  Password: @CSyH7IV8r4TUnaA3A7lu^2T
  Port: 3306
  Properties: 'verifyServerCertificate=false&useSSL=false&useUnicode=true&characterEncoding=utf8'
```
