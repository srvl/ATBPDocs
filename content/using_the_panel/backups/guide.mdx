## Introduction

Every ATBP Hosting plan includes a set number of backup slots. See the [backups overview](/plans/backups) and the plan tables for how many slots your plan has.

You can create backups manually or on a schedule, and later [download](#downloading-backups), [restore](#restoring-backups) (all of it, or [single files](#restoring-single-files-or-folders)), [lock](#locking) or [delete](#deleting-backups) them. All of this is done from the **Backups** tab of the panel at https://panel.atbphosting.com.

<Callout type="warning">

Backups are provided but not guaranteed. Download a backup now and then and keep your own copy of anything important.

</Callout>

---

## What a backup includes

A backup is a copy of every file on your server's **Files** page: worlds, player data, plugins, mods and their configs, and `server.properties`. Only files or folders you list to ignore are left out. Backups are stored apart from your server's files, so they do not count toward your disk, and resetting your world, deleting files, reinstalling or changing the server software does not delete your backups.

Databases from the **Databases** tab are not part of a backup; export them separately if your plugins use one.

### Leave files out of every backup

Create a file named `.pteroignore` in the main folder of your server, with one rule per line. Every backup follows it, including scheduled backups and Auto Backups, so anything it lists cannot be restored from them. A list typed into **Create Backup** adds to these rules for that backup.

The rules work like a `.gitignore` file:

| Line | What it leaves out |
|---|---|
| `plugins.zip` | Every file or folder with that name, in any folder |
| `archive-*.tar.gz` | Every matching file, in any folder. `*` stays inside one folder name |
| `world/data` | That path, counted from the main folder |
| `/old.zip` | Only the one in the main folder |
| `schemtest/` | The contents of every folder with that name, not a file with that name |
| `!plugins/keep.jar` | Nothing: it puts a file back that an earlier line left out |

Blank lines and lines starting with `#` are skipped. A list can have up to 256 rules.

## Manual backup creation

![The Backups page with the Create Backup button](/screenshots/panel-backups.webp)

1. Open your server in the panel and go to the **Backups** tab.
2. Click **Create Backup**.
3. Optionally give it a name, and optionally list files or folders to ignore.
4. Confirm. The backup runs in the background with a progress bar and may take a while on large servers.

If all your backup slots are used, you need to delete or [unlock](#locking) an old backup before creating a new one. If you need more slots, you can add **Extra Backups** from billing, see [Backups](/plans/backups).

## Automatic backup creation

You can use the [schedules feature](/using_the_panel/schedules) to create backups automatically.

1. Open the **Schedules** tab and create a new schedule (for example, daily).
2. Add a step with the action **Create backup**. Tick **Wait for the backup to finish** if later steps (such as a restart) should wait for it.
3. Save the schedule and make sure it is turned on.

When all your backup slots are full, a scheduled backup deletes your oldest **unlocked** backup to make room. It never deletes an Auto Backup, because those do not use your slots. [Lock](#locking) any backup you want to keep for good.

Very frequent backup schedules (for example hourly on a big world) can cause lag. Daily is enough for most servers.

## Restoring backups

A restore puts back every file in the backup and overwrites the same files on your server. To bring back only some files or folders, use [Browse files](#restoring-single-files-or-folders) instead. Make a fresh backup of the current state first if you might need it. Restored files count toward your disk like any others, so check that they fit.

To restore a backup, stop your server, open the **Backups** tab, click the menu on the backup you want, and choose **Restore**. Confirm the prompt and wait for the restore to finish before starting the server again. Press **Restore** once: restores are queued, and pressing the button repeatedly causes a "too many attempts" error. If a backup is running on the node, the restore or download waits for that one to finish and then goes ahead of any queued backups. When the restore deletes your current files first, it reads the whole backup before it deletes anything, so if a restore fails your server is left exactly as it was.

A big backup can take 10 to 15 minutes or more to restore. If the page shows `Request failed with status code 504` or `timeout of 20000ms exceeded` while it runs, only the page stopped waiting. The restore keeps going on the server, and the **Activity** tab fills with files being written back. Do not press **Restore** again. Leave the server off and wait until the files stop changing.

### Restoring single files or folders

You do not have to restore a whole backup to get one world, one plugin folder or one config file back.

1. Open the **Backups** tab and click **Browse files** on the backup you want. It is on your own backups and on Auto Backups.
2. Click a folder to open it. The line at the top shows where you are, and each part of it is a link back.
3. Tick the files or folders you want. Your ticks are kept while you move between folders. You can pick up to 200 at once; to bring back many files, tick the folder that holds them.
4. Click **Restore selected** and confirm. The server has to be stopped while files are restored. If it is running, the button reads **Stop server and restore** and stops it for you.
5. Wait for the message that says how many files were restored, then start the server.

Files from the backup replace files with the same name. Nothing else on your server is deleted or changed, so a world or plugin that was added after the backup stays where it is. Restored files count toward your disk.

Subusers need the **Restore** permission for backups to see **Browse files**.

### Plugins show red after a restore

If some plugins load but others show red in `/plugins`, the restore did finish: it never restores only part of your plugins. The cause is almost always the Minecraft version or the Java version, not the backup. Check that the version in **Startup** is the one the backup was made on, and that the **Docker Image** in **Startup** suits that version (newer Minecraft versions need a newer Java). See [Changing Java Version](/running_a_server/java-version). Restoring the same backup again will not change anything.

## Downloading backups

Open the **Backups** tab, click the menu on a backup and choose **Download**. Your browser will download the backup as an archive. If a backup will not download, the archive may be very large; create a fresh backup that ignores folders you do not need, or download the files you need with [SFTP](/using_the_panel/sftp).

Download links are private to your account and expire after a short time, so keep them to yourself.

A download or restore has to wait for any backup that is running on the same machine, so it can take a few minutes to start. If it stops with an error, try again a few minutes later.

---

## Locking

Locking a backup protects it from being deleted by accident. A locked backup cannot be deleted until you unlock it.

Use the menu on the backup and choose **Lock** (or **Unlock** to undo it).

---

## A backup is stuck on "creating backup"

Backups of big servers take a while, because every file is copied and compressed. There is no button to cancel a backup while it runs. While you wait:

- Check **Schedules** for a backup task that runs often. A schedule that starts a new backup every few minutes keeps one running all the time.
- Don't press restore or start another backup on top of it.

If the same backup still says "creating" after 30 minutes, open a **Hosting Support** ticket on [Discord](https://discord.atbphosting.com) with your panel link.

## Files or plugins went missing

We do not remove files from your server. When a folder such as `plugins` or your world is suddenly gone or smaller, the usual cause is a delete from the **Files** page by someone with access to the server, or a plugin. To find out and get them back:

1. Stop the server, so nothing writes over what is left.
2. Open the **Activity** tab and look for file deletes around the time it happened. Each entry shows the account, the time and the IP address. If you do not recognize it, change your password and check who has access in [Users](/using_the_panel/users).
3. Look in the [Trash Bin](/using_the_panel/file-manager-controls#trash-bin) in **Files**. Files moved to the trash can be restored until it is emptied.
4. Otherwise, [restore](#restoring-backups) the newest backup that still has the files. Check both your own backups and the Auto Backups.

Those are the only copies. Staff have no older snapshot or other copy of your server, so a file that is not in the Trash Bin or in a backup cannot be recovered. Make a backup before any big change, and keep your own copy of work you cannot lose.

## Deleting backups

If you no longer need a backup, use the menu on it and choose **Delete**. This frees up a backup slot. It does not free disk space, because backups are not stored on your server's disk. Auto Backups, the system backups we take each night, have no delete option, and staff cannot remove them for you either. They are kept in case of an emergency and replaced by themselves, and they use none of your disk or slots, so you can ignore them.

<Callout type="warning">

Deleting is irreversible. Deleted backups cannot be recovered. Backups are also deleted when a server is deleted, for example 3 days after an unpaid due date. Only the saved backup taken at suspension stays downloadable from billing for 30 days; see [suspensions and terminations](/billing/suspensions_and_terminations).

</Callout>
