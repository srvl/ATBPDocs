All the files below are in **Files**, `.cache`, `Server` in the [panel](https://panel.atbphosting.com). The settings file is named after your server, `servertest.ini` by default. Stop the server before editing it.

## Build 41 or Build 42

Build 42 is the current version and what new servers run. Build 41 is still available on Steam as the `legacy41` branch.

| Your situation | Run |
| --- | --- |
| New server or new world | Build 42 |
| Keeping an old Build 41 world | Build 41 |
| Mods that only support Build 41 | Build 41 |

- Server and every player must be on the same build. Players switch in Steam: right-click Project Zomboid, **Properties**, **Betas**.
- Build 41 and Build 42 worlds are not compatible. Back up before switching.
- To run Build 41, set the Steam beta branch to `legacy41` on the **Startup** tab if your server shows that field, then press **Reinstall Server** under **Settings**. If there is no such field, open a ticket and we will set it.

## Make the server private

- **Password:** set `Password=` in the settings file. Players type it in the server password box when they add the server.
- **Whitelist:** set `Open=false`. Only players with an account on the server can join. Add them from the **Console**:

| Command | What it does |
| --- | --- |
| `adduser <username> <password>` | Creates an account for a player |
| `addusertowhitelist <username>` | Whitelists a player who is online now |
| `addalltowhitelist` | Whitelists everyone online |
| `removeuserfromwhitelist <username>` | Removes a player |

Other related settings: `AutoCreateUserInWhiteList=true` adds new joiners automatically, `DropOffWhiteListAfterDeath=true` removes players when they die, and `Public=false` hides the server from the public list.

## "Workshop version mismatch" when joining

The server has an older copy of a mod than the player, or the reverse.

1. Stop the server.
2. In **Files**, open `steamapps/workshop` and delete `appworkshop_108600.acf`.
3. Start the server. It checks every Workshop mod for updates, which can take a few minutes with many mods.

If one player still gets the error, they unsubscribe from all Project Zomboid Workshop items in Steam and join again; the game downloads the right versions.

## "No space left on device" on startup

If the Console shows `java.io.IOException: No space left on device` right after `Start making backup`, the startup backup is opening too many files at once (big saves have tens of thousands of files). It is usually not your disk.

1. Stop the server and open the settings file.
2. Change `BackupsOnStart=true` to `BackupsOnStart=false`.
3. Save and start the server.

Keep regular backups with the panel's **Backups** tab instead. If your disk really is full, see [disk full](/using_the_panel/stuck-server#disk-full).

## "Port Closed" warning

This warning means the player is connected through Steam Relay instead of directly. The server still works, but play can be laggier.

- Join from **Multiplayer**, **Favorites** with the IP and port from the panel, with **Use Steam Relay** unticked. Joining from a Steam invite always uses the relay.
- If you uploaded your own `.ini`, its `DefaultPort=` and `UDPPort=` must match the ports your server has in the panel, not the game's defaults of 16261 and 16262. Fix them and restart.

There is no router setup to do on our side: every port listed on your server's **Network** tab is already open.

## Stuck on "Getting Server Info"

The game port answers but the second port the game needs does not. Project Zomboid uses two ports, and both must be ports your server has on the **Network** tab. A port number you type into **Startup** or the `.ini` yourself is closed on purpose, even if the server starts on it.

1. Open **Network** and check which ports your server has. If it has only one, add one from the **Other games** range (see [Adding ports](/using_the_panel/adding-ports)).
2. On **Startup**, or in the settings file as `DefaultPort=` and `UDPPort=`, use only those port numbers. Leave out the game's defaults (16261 and 16262) and any number that is not on the **Network** tab.
3. Restart the server and join again with the IP and main port from the panel.

## Use ports from the Other games range

Both of your Project Zomboid ports should come from the **Other games** range (41000 and up). Ports from the Minecraft ranges, such as **Minecraft Bedrock / Geyser** (19200 and up) or **Minecraft Java** (25600 and up), are filtered by our network protection for Minecraft traffic only. A Zomboid server on one of them starts fine, but players get stuck on **Getting Server Info** or cannot find it.

If your main port is in a Minecraft range, add a port from **Other games**, click **Make Primary** on it, and use a second **Other games** port for `UDPPort=`. See [Moving an existing port](/using_the_panel/adding-ports#moving-an-existing-port).

## "Connection Startup Failed. Code: 5" on startup

The server stops right after start with `java.net.ConnectException: Connection Startup Failed. Code: 5` and `UdpEngine` in the error. The game could not open its network port, almost always because the main port and the second port are set to the same number.

1. Stop the server.
2. On **Startup** (or in the settings file), set the main port and the second (Steam or UDP) port to two **different** ports from your **Network** tab.
3. Start the server again.
