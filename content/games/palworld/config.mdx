Palworld reads its options from one long `OptionSettings=` line in `PalWorldSettings.ini`.

<Callout type="warning">

Always stop the server before editing. Palworld rewrites the file when it shuts down, so changes made while it runs are lost.

</Callout>

## Edit the settings file

1. Stop the server in the [panel](https://panel.atbphosting.com).
2. If the setting you want is listed on the **Startup** tab, change it there instead. Startup values are applied when the server starts, so a hand edit of the same setting would be replaced.
3. For everything else, open **Files** and go to `Pal/Saved/Config/LinuxServer/PalWorldSettings.ini`.
4. If the file is empty, copy everything from `DefaultPalWorldSettings.ini` in the main folder into it, then delete the lines above `[/Script/Pal.PalGameWorldSettings]`.
5. Change the values you want, save, and start the server.

Use decimals for rates, for example `ExpRate=2.000000`, not `ExpRate=2`. Text values go in quotes, for example `ServerName="My Server"`.

A community generator such as [pal-conf](https://pal-conf.bluefissure.com/) can build the whole line for you to paste in.

## Settings people change most

| Setting | Default | What it does |
| --- | --- | --- |
| `ServerName`, `ServerDescription` | | Name and description in the server list |
| `ServerPassword` | empty | Join password |
| `AdminPassword` | empty | Password for `/AdminPassword` (see [admins and commands](/games/palworld/admin)) |
| `ServerPlayerMaxNum` | 32 | Maximum players |
| `ExpRate` | 1.0 | Experience gained |
| `PalCaptureRate` | 1.0 | How easy Pals are to catch |
| `PalSpawnNumRate` | 1.0 | How many Pals spawn. Higher uses more CPU and RAM |
| `DayTimeSpeedRate`, `NightTimeSpeedRate` | 1.0 | Length of day and night |
| `PalEggDefaultHatchingTime` | 72.0 | Hours to hatch an egg |
| `WorkSpeedRate` | 1.0 | How fast Pals work at bases |
| `DeathPenalty` | All | `None`, `Item`, `ItemAndEquipment` or `All` dropped on death |
| `bIsPvP`, `bEnablePlayerToPlayerDamage` | False | Player versus player |
| `bEnableInvaderEnemy` | True | Raids on bases. Turning it off saves memory |
| `DropItemMaxNum` | 3000 | Items allowed on the ground at once |
| `DropItemAliveMaxHours` | 1.0 | Hours before dropped items vanish |
| `BaseCampMaxNum`, `BaseCampWorkerMaxNum` | 128, 15 | Bases in the world, worker Pals per base |
| `GuildPlayerMaxNum` | 20 | Players per guild |
| `bEnableFastTravel` | True | Fast travel points |
| `bHardcore`, `bPalLost` | False | Permadeath for players, and Pals lost for good on death |
| `CrossplayPlatforms` | (Steam,Xbox,PS5,Mac) | Which platforms can join |

Some options exist in the file but do nothing in the current game version. If a change has no effect after a restart, that is usually why.

## Settings not applying after a world upload

If you uploaded a world from single player, co-op or another host, its folder may contain a `WorldOption.sav`. When that file is there, Palworld uses the settings saved inside it and ignores `PalWorldSettings.ini`, including the passwords.

To go back to the settings file:

1. Stop the server.
2. In **Files**, open `Pal/Saved/SaveGames/0/` and then your world folder (the long letters-and-numbers name).
3. Download `WorldOption.sav` as a backup, then rename it to `WorldOption.sav.old`.
4. Check your values in `PalWorldSettings.ini` and start the server.

Hardcore and randomizer options are the exception: some game versions only read them from `WorldOption.sav`. If you need those, keep the file and replace it whenever you change settings.
